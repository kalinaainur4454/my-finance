# PRD: Приложение «Мои финансы»

## 1. Обзор продукта

**Название:** Мои финансы
**Тип:** персональное веб-приложение для учёта финансов (один HTML-файл)
**Дата создания PRD:** 7 ноября 2026
**Статус:** первая версия (v1) реализована

«Мои финансы» — простое приложение для личного контроля расходов и доходов, планирования бюджета, отслеживания целей накоплений и учёта инвестиций в ценные бумаги. Приложение работает локально в браузере, не требует регистрации, интернет-соединения (после первой загрузки) и установки.

## 2. Цель и проблема

**Проблема:** пользователю нужен простой способ видеть, куда уходят деньги, контролировать месячные траты, копить на цели и отслеживать свои вложения — без сложных сервисов, подписок и передачи данных третьим лицам.

**Цель продукта:** дать одному пользователю (владельцу) наглядный инструмент ежедневного учёта личных финансов, который открывается как обычный файл и работает и на телефоне, и на компьютере.

**Целевая аудитория:** один пользователь — сам владелец продукта. Публичное распространение, многопользовательский режим и регистрация не требуются.

## 3. Ключевые решения и ограничения

- **Формат:** единственный HTML-файл (`мои-финансы.html`), открывается двойным кликом в любом современном браузере (Chrome, Safari, Edge).
- **Платформы:** телефон и компьютер — адаптивная вёрстка под оба типа экранов.
- **Хранение данных:** локально в браузере (localStorage). Данные не покидают устройство. Сервер, база данных и бэкенд отсутствуют.
- **Валюта:** тенге (₸). Пользователь находится в Казахстане.
- **Зависимости:** единственная внешняя зависимость — библиотека Chart.js, загружаемая с CDN при открытии файла (нужен интернет только для отрисовки графиков; весь остальной функционал автономен).
- **Приватность:** никакой аналитики, аккаунтов и передачи данных.

## 4. Функциональные требования

### 4.1. Учёт операций (расходы и доходы)

- Добавление операции: сумма, тип (расход/доход), категория, комментарий (необязательно), дата.
- Переключатель «Расход / Доход» с разными наборами категорий:
  - Расходы: Продукты, Кафе и рестораны, Транспорт, Жильё и коммуналка, Связь и интернет, Здоровье, Одежда, Развлечения, Образование, Дети, Подарки, Прочее.
  - Доходы: Зарплата, Подработка, Подарки, Возврат, Прочий доход.
- Список операций за выбранный месяц, отсортированный по дате (новые сверху).
- Удаление любой операции.
- Навигация по месяцам (кнопки ‹ ›).
- Сводка за месяц: сумма доходов, сумма расходов, остаток (с цветовой индикацией).

### 4.2. Наглядные графики

- Круговая диаграмма расходов по категориям за выбранный месяц (Chart.js, тип doughnut).
- Подсказки при наведении с суммами в тенге.
- Сообщение-заглушка, если расходов за месяц нет.

### 4.3. Лимит на месяц (бюджет)

- Задание месячного лимита расходов в тенге.
- Прогресс-бар: потрачено / лимит.
- Цветовая индикация: синий < 70%, оранжевый 70–99%, красный ≥ 100%; при превышении выводится пометка «превышение!».
- Возможность изменить или снять лимит.

### 4.4. Цель накоплений

- Задание цели: название (например, «Отпуск») и сумма.
- Внесение произвольных сумм в «копилку» цели.
- Прогресс-бар с процентом выполнения.
- Поздравление при достижении цели.
- Редактирование цели с сохранением уже накопленной суммы.

### 4.5. Учёт инвестиций в ценные бумаги

- Добавление бумаги: название, количество, цена покупки за штуку, текущая цена за штуку.
- Сводка по портфелю: всего вложено, текущая стоимость, доходность в тенге и процентах (с цветовой индикацией прибыль/убыток).
- По каждой бумаге: количество, цена покупки, текущая цена, прибыль/убыток по позиции, текущая стоимость позиции.
- Ручное обновление текущей цены (кнопка «✎») — пользователь сверяется с приложением своего брокера.
- Удаление позиции.
- Дисклеймер: приложение ведёт только учёт и не даёт инвестиционных рекомендаций; котировки не подгружаются автоматически.

## 5. Нефункциональные требования

- **Простота использования:** целевой пользователь — новичок без опыта программирования; интерфейс на русском языке, без технического жаргона.
- **Адаптивность:** корректное отображение на экранах от ~360px (телефон) до десктопа; сетка карточек перестраивается автоматически.
- **Надёжность хранения:** данные сохраняются при каждом изменении; при повреждении данных в localStorage приложение запускается с чистого состояния, не падая.
- **Производительность:** мгновенный отклик; объём данных (тысячи операций) обрабатывается на клиенте без задержек.

## 6. Вне scope (осознанно не делается)

- Регистрация, аккаунты, многопользовательский режим.
- Сервер, облачная синхронизация между устройствами.
- Автоматический импорт банковских выписок и подключение к брокерским API.
- Автоматическое обновление котировок ценных бумаг.
- Мультивалютность (только ₸).
- Инвестиционные рекомендации и аналитика рынка.

## 7. Известные ограничения и риски

- **Привязка к браузеру:** данные хранятся в конкретном браузере на конкретном устройстве. Очистка данных браузера удалит историю. Синхронизации между телефоном и компьютером нет — фактически это два независимых журнала.
- **Зависимость от CDN:** без интернета не отрисуется график (остальной функционал работает).
- **Ручное обновление цен:** инвестиционный блок требует дисциплины — цены обновляются вручную.

## 8. Возможные следующие шаги (backlog)

- Экспорт/резервная копия данных в файл (JSON/CSV) и импорт — снимает риск потери данных и частично решает перенос между устройствами.
- Импорт операций из банковской выписки (CSV/Excel).
- График динамики доходов/расходов по месяцам.
- Повторяющиеся операции (подписки, зарплата) с автодобавлением.
- Несколько целей накоплений одновременно.
- Учёт продажи бумаг и дивидендов в инвестиционном блоке.

## 9. История принятия решений

- Первоначальный запрос сформулирован как «приложение для контроля расходов и доходов»; в ходе уточняющих вопросов пользователь выбрал веб-формат.
- На этапе выбора аудитории возникла путаница с термином «продукт для всех» — после уточнения подтверждено: приложение нужно **только для личного использования**. Отсюда отказ от бэкенда и регистрации в пользу одного локального HTML-файла.
- Блок инвестиций добавлен по запросу пользователя уже после начала разработки; реализован в учётном (не рекомендательном) режиме с ручным обновлением цен.
